Without Relay

Session Crash

Agent hits the context limit mid-refactor. Session dies. You restart from scratch, losing all decisions, failed attempts, and partial work. The agent will repeat the same mistakes.

Naive Truncation

Silent Amnesia

Old messages are quietly dropped. The agent loses track of earlier decisions, re-reads files it already knows, retries failed approaches, and produces duplicate or regressed edits.

Relay

Structured Handoff

At 85%, Relay captures goal state, decision log, rejected approaches, and file diffs. A fresh agent instance resumes with full knowledge of where it left off — and what not to try again.

Architecture

Four steps to perfect handoff

Relay is a thin middleware layer. It intercepts agent sessions, structures their state, and resumes seamlessly — without modifying the underlying agent.

01
Checkpoint Trigger

Relay monitors token consumption in real-time. At 85% context capacity, a checkpoint is triggered automatically — before the agent risks losing state.

threshold: 0.85 × context_limit
trigger: token_count ≥ threshold
latency: < 50ms (non-blocking)
agent: continues working during capture
⚡
02
Hybrid Compression

State is compressed using a hybrid strategy — not just an LLM summary. Relay preserves structured data that summaries typically lose: decision logs, rejected approaches, and git diffs.

layer-1: LLM narrative summary (goal + progress)
layer-2: structured decision log (JSON)
layer-3: rejected approaches + dead ends
layer-4: git diff + AST snapshot
layer-5: top-k tool outputs (by relevance)
🗜
03
Graph-Aware Retrieval

Before handing off, Relay uses graph-aware retrieval to surface the most relevant context — files in the dependency graph, related git commits, and AST-linked modules — not just semantic similarity.

backend: Qdrant vector store
signals: dependency graph + import graph
re-rank: recency × relevance × code coupling
output: top-k files + chunks injected into prompt
🔍
04
Agent Handoff

A new agent instance is initialized with the compressed checkpoint and retrieved context injected as a structured system prompt. The agent resumes the task without re-reading files or retrying dead ends.

handoff: relay-session-{id}.json → system prompt
includes: goal · decisions · why-not store · context
target: OpenHands · Claude Code · any HTTP agent
latency: ~1.8s end-to-end checkpoint + resume
▶
Standard Checkpoint Fields
  • Original task goal and acceptance criteria
  • Completed sub-tasks with status
  • Pending items and current focus
  • Files modified (paths + git diff)
  • Latest tool outputs (test results, errors)
🆕 Relay's Key Innovation
  • Rejected approaches — what was tried and why it failed
  • Known dead ends — paths confirmed not to work
  • Design decisions — rationale behind current approach
  • Dependency graph snapshot — code coupling map
  • AST delta — structural changes since session start
Retrieved at Handoff
  • Top-k semantically relevant code chunks
  • Imported modules in scope of active changes
  • Related commit history (last N commits on touched files)
  • Test fixtures for failing tests
Agent Compatibility
  • OpenHands — native session hook
  • Claude Code — context injection via system prompt
  • Any HTTP agent — REST API (POST /checkpoint, POST /resume)
  • LangGraph — middleware node (in roadmap)

Design Decisions

Why Relay
outperforms

The architecture is opinionated. Here's what makes the difference over naive approaches.

🚫
The "Why NOT" Store

Relay records rejected approaches and confirmed dead ends. Without this, fresh agents repeat the same failed experiments — wasting tokens on approaches already proven wrong. This is the highest-impact addition over standard checkpointing.

🌳
Dependency Graph Retrieval

Semantic search alone retrieves thematically similar text. Code needs structural awareness — what files are coupled, what imports what, what changed downstream. Relay uses the project's dependency graph as the primary retrieval signal.

🗜
Hybrid vs. Summary-Only

LLM summaries lose precise information: exact error messages, specific line numbers, tool output values. Relay preserves these in structured JSON layers alongside the narrative summary, so the resumed agent gets both high-level context and precise details.

📐
Objective Continuity Metrics

RelayBench avoids LLM-as-judge for core metrics. Instead: repeated edits, reverted code, duplicate patches, and regression test deltas — all measurable objectively. LLM scoring is used only for qualitative narrative assessment.
